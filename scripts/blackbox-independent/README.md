# 星雾探测：独立规则与题库验证

这组 Python 代码只解析题库与运行时常量中的 JSON，不导入、不执行任何生产 JavaScript/TypeScript，也不编译或运行上游 C。没有第三方 Python 依赖。

## 复现

放入仓库 `scripts/blackbox-independent/` 后，从仓库根目录运行：

```sh
python3 scripts/blackbox-independent/selftest.py --all-small-boards
python3 scripts/blackbox-independent/validate_campaign.py --repo . --output docs/blackbox/independent-report.json
python3 scripts/blackbox-independent/test_validator_mutations.py --repo .
```

可选全量生产差分数据：

```sh
python3 scripts/blackbox-independent/emit_vectors.py --output /tmp/blackbox-oracle-vectors.json
```

输出覆盖 3×3、4×4、5×5，每种 1–4 星的全部 18,046 布局及 348,816 个端口响应。生产端可以逐项比较自己的完整签名；这一步由外部测试调用生产代码，不让 Python oracle 依赖生产实现。约 1.8 MB 的输出不必提交入库。

可选独立统计：

```sh
python3 scripts/blackbox-independent/oracle.py --exhaustive --output /tmp/blackbox-universes.json
python3 scripts/blackbox-independent/analyze_difficulty.py
```

`analyze_difficulty.py` 的规范方向采用数值元组最小值；生产证书 `canonical` 则采用字符串字典序最小值。两者划分相同 D4 等价类，但同一类的代表方向可能不同，继而影响固定端口平局规则下的策略步数。关卡正式证据以 `validate_campaign.py` 对实际方向的逐步重算为准，不挪用辅助统计里的方向样例。

## 固定规则合同

- 格子是行优先下标，左上角为 0。
- 端口为 `0..4n-1`：北边 x 从左到右；东边 y 从上到下；南边 x 从左到右；西边 y 从上到下。南、西两边不是顺时针编号。
- 响应 `-1` 为吸收，`-2` 为反射，非负整数是出口端口。
- 发射位置在盘外。先查正前格：有星就吸收；否则任一前角有星就直接记入口反射；两者都没有才进入第一格。
- 盘内每次先查正前格。正前有星时吸收，优先级高于前角。
- 仅左前有星，原地右转 90°；仅右前有星，原地左转 90°；两前角都有星，原地转 180°；随后重新检查新方向。转弯本身不移动到下一格。
- 三个前方格都没有星才前进一格。走出边界时返回出口；出口与入口相同则记反射。
- 不能把“吸收”简单解释为此行/此列直线可见一颗星：光束可能转弯后才被吸收。
- 访问状态必须含格子和方向。重复状态是实现/输入异常，抛出 `RayCycle`，绝不伪装成反射。

上游使用“正前吸收，左前则右转并原地重查，右前则左转并原地重查”的顺序实现，没有单独双侧分支。独立测试穷尽验证这与上述双侧直接掉头模型在支持范围内每个边缘发射完全相同。它不是对任意尺寸、任意内部起始状态的无限范围证明。

## 可辨识性、互逆与循环

完整观测签名是所有 `4n` 个端口的响应向量，入口/出口按实际端口位置比较，不按界面临时配对编号比较。固定星数条件下，胜利必须接受任意与目标完整签名相同的合法布局，不能比较预置星位。

最小回归见证：3×3 两星 `[0,8]` 与 `[2,6]` 的完整签名相同：

```json
[-1,-2,-1,-1,-2,-1,-1,-2,-1,-1,-2,-1]
```

因此“星数不超过 4 就唯一”是错误的，不能从官方的五球示例反推这一保证。对于 5×5 四星，12,650 个布局划成 12,264 个完整签名类：11,985 个布局唯一，279 个类包含多个布局，最大一类有 29 个布局。唯一布局有 1,572 个 D4 类，足够选择原创且非旋转/镜像重复的题库。

每次从 p 贯通到 q 时，反向从 q 发射必然回到 p，所以一条观测可以同时记录两端；不应重复收费或重复计探测。吸收与反射没有可推断的“另一端”。

盘内可以存在不可从边缘进入的封闭循环：3×3 四角都是星时，从中心格向任意方向开始会不断转向。边缘发射不能到达该内部状态。本次穷尽所有 ≤4×4 任意星数，以及 5×5 的 1–4 星，没有发现边缘可达循环；仍保留显式异常保护。

## 公平候选与提示

固定大小和星数的全部组合构成候选全集。候选过滤只读已公开探测 `(port,result)`，包括其互逆信息；玩家的星标/空格笔记不参与过滤。

- 必为星：所有候选星位的交集。
- 必为空：所有候选星位并集的补集。
- 候选为空：公开证据矛盾或存档损坏，不应挑某个预置答案继续提示。
- 推荐探测：按候选响应分桶，最小化 `sum(bucketSize²)`；平局按最大桶大小，再按端口编号。此为均匀布局先验下最小期望剩余候选，不是最小化最坏情况的优先策略，也不保证全程最少探测。
- 所有候选完整签名相同时，没有进一步可分辨探测，即便候选数仍大于 1。等价布局都应被判定可接受。
- 提示 API 不接收秘密目标星位；实际探测响应才需要读取目标。

## 84 关逐项验证范围

`validate_campaign.py --repo ... --output ...` 验证：

1. 六章 84 关，章数量分别为 3、9、12、16、20、24，尺寸/星数为 (3,1)、(4,2)、(4,3)、(5,2)、(5,3)、(5,4)。
2. 格子下标、星数、ID、章节、排序合法。
3. 每关签名由独立几何重新生成，并检查贯通互逆。
4. 重新穷举对应星数的整个布局全集，签名恰好唯一。
5. 旋转/镜像八种形式计算字典序 canonical，组合尺寸后全库去重。
6. 每个 `probeTrace` 的推荐端口、响应、最坏桶、分桶数、响应后候选数量逐项重算；最终恰好剩一布局。
7. 策略步数、边缘星数、正交邻接星对数、吸收/反射/贯通端口数和统计全部重算。
8. 同章策略步数不递减；第四章扩大为 5×5 同时退回两星，这是设计缓冲，不宣称跨章难度严格递增。
9. 从 `src/games/blackboxLevels.ts` 解析 JSON 常量，确认与证书的题目与章节相同。不会将 TS 当代码执行。

首次验证实际范围为 15,939 个布局、315,988 个端口，84 关全部通过；章内策略探测范围为 2–2、2–4、3–8、2–5、3–9、4–12。报告附完整文件哈希，题库修改后须重跑，不能沿用旧结论。

## 自测与证书防篡改

`selftest.py --all-small-boards` 覆盖 81,341 布局、1,360,356 个端口，两种独立数据结构/转向方式交叉核对，0 差异、0 互逆失败、0 可达循环。另有 161,888 个 D4 端口变换检查。基本测试包括空盘、正前吸收优先、入口邻角反射、左右转向、双侧掉头、官方图示端点、等价见证、不可达内部循环、候选事实与非法输入。

`test_validator_mutations.py` 将正确题库复制到临时目录后，故意修改响应、星位、canonical、推荐端口、候选数、最坏桶、分桶数、指标、等价盘、重复盘、运行时内容，13 类错误均必须被拒绝。不会修改原题库。
