# 煎饼翻排：120 关原创战役

## 规则与独立机制

一叠 3–8 片大小各不相同的煎饼，从上到下记为一个排列。选择第 k 层（2 ≤ k ≤ n），把它和上面的全部煎饼倒序；下方不动。目标为 `[1,2,…,n]`，小在上、大在下。通关不限制翻转次数，也没有计时要求。

这是前缀反转规划。它既不是栈与队列中的单件移出/入队，也不是排序网络中配置比较交换器后对全部输入验证。每次决定的是当前单个排列中一整段的边界，重叠翻转会改变先前整理的部分。

## 教学与选择

共六章，各章数量由题目与学习阶段决定，没有强制每章同数：

| 章节 | 关数 | 片数 | 精确最短步数 | 主要观察 |
|---|---:|---:|---:|---|
| 认准翻面范围 | 8 | 3–4 | 1–4 | 第一关一次翻转；逐步学习重叠反转 |
| 两次翻转相遇 | 12 | 4 | 2–4 | 先到顶部，再送到想要的位置 |
| 把大饼送到底 | 18 | 5 | 3–5 | 最大值逐层归位法与更短路线比较 |
| 留住好邻居 | 24 | 6 | 4–7 | 相邻连续值组成的片段如何合并和拆开 |
| 换条路线试试 | 26 | 7 | 5–8 | 比较多种首翻，不以眼前整齐代替距离 |
| 整叠的计划 | 32 | 8 | 6–9 | 在完整排列空间里规划路线 |

首章人工挑选教学排列，之后在确定性排序的候选池中按最短距离、单一/多个最优首翻、贪心是否绕路进行交错选样。排除初始目标、重复排列，并使后五章的最大片不预先固定在底部。关卡大小本身不另计为新游戏。

55 关的经典“最大值先归位”策略会比最短路线多用步数。题库允许多个最短解，不把证书中的一个路径当作唯一答案。最少步数是参考目标，超过也正常通关。

## 确切距离与运行时提示

`scripts/pancake/generate.mjs` 从每种尺寸的目标排列做完整反向 BFS。每次前缀反转是自己的逆操作，因此无向图中的距离就是正向整理所需的最少次数。不是把随机打乱次数当成最少步数。

- 3、4、5、6、7、8 片分别有 6、24、120、720、5,040、40,320 种排列。
- 共 46,230 个状态、316,644 条有向合法边。
- 各尺寸直径为 3、4、5、7、8、9。
- 120 关的最短解证书共 634 次翻转。

距离以零基 Lehmer rank 索引的单字符字符串保存，仅在新游戏模块按需加载。提示最多检查当前局面的 7 个合法翻转，选择一个距离减一的候选；无需在手机主线程重新 BFS，也不自动执行。提示明确说明依据是精确距离表，而非冒充人工逻辑推导。

运行时关卡不含 `solution` 或 `features`。完整证书、最优首翻、贪心步数和断点数只在 `docs/pancake/campaign.json`。目标顺序属于公开规则，展示它不是泄露隐藏答案。

## 交互、暂停与恢复

每层是至少 50px 高的宽触控区，数字与条带宽度同时表达大小。先点一层，范围虚线与上下箭头标出全部待翻部分，独立预览显示确认后的完整顺序；再点同层或确认按钮才改变局面。取消不计步。

键盘用 Tab 进入堆栈、上下方向键选择层数、Home/End 移动到首末可选层、Enter/空格预览及确认。Ctrl/Meta/Alt 组合键不改变游戏。控件以层数保持稳定身份，翻转后焦点仍在对应层；换关由外壳恢复标题焦点。Escape 暂停/恢复。

暂停时输入禁用，暂停期间传入的提示/撤销事件会消费而不会在恢复时积压执行。通关只报告一次，完成后编辑及撤销锁定；重来或换关开始新一轮。

每关保存 ID、当前排列、动作数和全部撤销链，读取时逐条验证必须从该关初始排列出发、每一步恰为合法反转，且不能从已完成状态继续。损坏或其他关的存档回退到开局。没有有效动作链的伪造完成状态不被接受。动作链超过 4,096 步时仍能继续游戏和撤销，但暂不更新跨刷新存档，并明确提示当前未保存；撤销回上限以内后恢复保存。载入边界避免恶意大存档拖慢页面。

显式 `freshStart` 重来信号只由本模块消费，避免外壳 keyed remount 时 `removeItem` 失败却重新读入旧局。其他游戏玩法未改动。存储禁用时仍可游玩。

## 可重复验证

```bash
node scripts/pancake/generate.mjs --check
node scripts/pancake/verify-runtime.mjs
python3 -m unittest discover -s scripts/pancake-independent -p 'test_*.py'
python3 scripts/pancake-independent/verify.py --repo . --self-test --output /tmp/pancake-independent-report.json
npm run typecheck
npm test
npm run build
npx playwright test e2e/pancake-campaign.spec.ts
npx playwright test --config=playwright.pages.config.ts
```

独立 Python 验证器不导入 JS 生成器或 TS 逻辑，重建全部图，使用字典序排列独立核排名与每个距离字符，并独立复放证书、核最优开局/贪心/断点、ID/排列去重及两份静态数据一致。另有负向 mutations，防止验证器只接受正确样本。

原生 Node 24 直接运行真实 TS 规则和存储代码，检查全部状态/合法动作、精确下降提示、全部证书、每个证书前缀的恢复、非法输入和终态锁定。DOM 测试通过真实按钮完成每关并覆盖中断与损坏存档；浏览器每五关一个场景，在既有 1536×1024 桌面与 390×844 手机尺寸下完成全部 120 关。

每章首、中、末保留开局、预览、完成截图。专项场景另外覆盖键盘与修饰键、暂停、撤销、提示、重来、换关和刷新恢复。Pages 预览与真实公网均从第 120 关的合法中局刷新继续，并核精确 SHA 标记和真实通关存档。验证结果应以对应提交的 GitHub Actions 和实际截图复核为准，不能把源码检查当作浏览器通过。

本地云工作区没有 npm 依赖，原生 Node/Python 可实际运行；类型、DOM、构建和双尺寸 Chromium 由现有远端 CI 执行。没有验证真实 iOS/Android、Safari、Firefox、屏幕阅读器或完整 WCAG 合规性。
