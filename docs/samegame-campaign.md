# 花簇消除 · 100 关原创清空挑战

## 规则与完整玩法

Same Game 的同类连通消除与已有的 2048 合并、夹击翻色、联动熄灯不同：玩家选一簇至少两朵上下左右相邻的同类花，消除后同列花朵向下落，空列移除、右侧列向左收拢。对角不连接，没有自动连消。目标始终是清空所有花朵，没有分数门槛、步数限制、倒计时或付费道具。

第一次点按只选中花簇，同时在棋盘下方预览确认后的完整局面。再点同簇或点“确认消除”才执行；取消不改变棋盘。单朵或空地会解释原因。实际消除可撤销；胜利后按外壳协议锁定编辑、提示和撤销，重来开始新局。

全部核心操作都可触屏点击，也支持 Tab、方向键、Enter 和空格。固定棋盘槽位保留 DOM 身份，消除后键盘焦点不丢失；颜色同时配有圆瓣、菱瓣、星瓣和圆果符号与辅助名称。格子在 390px 手机尺寸为 46px，较窄尺寸保持至少 44px。Escape 暂停/继续，暂停期间预览与局面不改变。

当前局面和撤销历史保存在版本化的 `playgarden.samegame.v1` 本地存档中。读取时从原始题目逐步重放每一段合法历史，拒绝跨关、伪造清空、断裂历史、越界颜色、超长数组和坏 JSON；存储不可用时仍可玩并显示明确提醒。通关与收藏继续沿用现有 v2 进度。

## 五章与难度证据

每章 20 关，共 100 关。棋盘从 4×3 到 6×7，但尺寸只是其中一个变化。选关使用稳定 ID 和索引；若后续扩展，仅追加或明确迁移，不能悄悄重排存档。

| 章节 | 范围 | 教学与已验证的选题条件 | 完整状态数中位数 | 证书中有输赢选择的步数中位数 |
| --- | --- | --- | ---: | ---: |
| 认识花簇 | 1–20 | 小盘认识连通、预览及孤花风险；前五关至少两个安全开局 | 17.5 | 3 |
| 借一步下落 | 21–40 | 每份证书都有重力引发的新合簇；至少三个有输赢分支的选择点 | 65.5 | 4 |
| 给花列让路 | 41–60 | 每份证书都有空列收拢产生的新接触；至少四个混合选择点 | 429.5 | 7 |
| 留住花伴 | 61–80 | 至少六个混合选择点、三个仅一簇安全的选择点；15 关所有最大开局花簇必败 | 1251.5 | 8 |
| 规划整座花园 | 81–100 | 兼顾重力、收列与伙伴；至少八个混合选择点、四个仅一簇安全的选择点 | 7513.5 | 12 |

“状态数”是去除颜色重命名和合法左右镜像后的完整可达状态图节点数，包含胜利与失败终局；不是玩家需要尝试的次数。按剩余花朵数统计的最大状态分组量称为 peakFrontier，它不是 BFS 深度或实际队列长度。

“混合选择点”表示当前局面至少存在一个可清空选择和一个不可清空选择。“延迟陷阱”是消除后仍然有合法动作、但已不能全部清空的开局。它比立即出现无处可消的终局更能检验后续规划。63 关具有“所有最大开局花簇都必败”的严格反例，不依赖最大组并列时如何打破平局。固定“每次最大簇、同大时先选最靠前代表格”的贪心策略有 91/100 关失败。逐关结果、阈值、直方图与反例见 [完整证书](samegame/campaign.json)。

上述证书路径按最小安全花簇优先选取，是一条合法清空路线，绝非最短步数或最高分方案。路径指标不代表所有解都必须经历这些选择，也不是人类难度的客观分数。难度还需要真实试玩反馈。

## 原创来源与可复现生成

- 规则实现、生成器、100 个盘面、中文教学与程序化花朵插画均由本项目原创，没有复制第三方源码、商业关卡、角色、美术、音频或字体。
- 不新增依赖、外部请求、账号、广告、追踪或排行榜；沿用项目 GPL-3.0-only 许可证。
- 固定 xorshift32 PRNG 和种子 `0x53414d45`，每个候选至多 50,000 个对称缩减状态、每关至多 10,000 次候选。超预算候选直接舍弃，不能按失败盘面计数。
- 生成器对被接纳的每个候选完整展开状态 DAG，不使用“某色只剩一朵”剪枝省略可达状态，因此统计覆盖全部可达状态与边。
- 去重只允许颜色重命名，以及“反转有花的列顺序后重新向左压紧”。旋转和上下翻转改变重力方向，不是这个游戏的对称性；固定宽度上直接反转残盘还会把空列放到左侧，也不能直接用作规范状态。
- 玩家模块只包含题目与章节信息，完整解法、路径及搜索统计保留在 docs 中，不被导入运行时。

重生成并核对逐字一致：

```bash
node scripts/samegame/generate.mjs --check
node scripts/samegame/verify-runtime.mjs
```

## 独立求解与运行时提示

独立 Python 验证器使用不同的列表示、连通搜索与规范键实现，重新搜索每关完整状态图，并检查全部证书、开局安全/失败分类、逐步选择与重力/收列证据。自测包含规则、对称性和篡改证书的反例。它不把作者的成功标记直接当作证明。

运行时提示从当前盘面另做有界搜索（默认与硬上限均为 30,000 个展开节点），不读取关卡证书。只有证明存在清空后续才选中下一簇；证明所有选择失败时建议撤销；预算耗尽返回“未找到可靠提示”，不会误报无解。提示只预选、不代替确认，也不声称最优。

```bash
python3 -m unittest discover -s scripts/samegame-independent -p 'test_*.py'
python3 scripts/samegame-independent/verify.py --repo . --output /tmp/samegame-independent.json
npm run typecheck
npm test
npm run build
npm run test:e2e
```

## 验收边界

- DOM 测试逐关真实点选/确认完成 100 关，校验预览不变更、当前局面提示、暂停 token 消费、撤销、同关重来、换关、StrictMode 单次通关和受损存档。
- 浏览器测试按五关短流程执行全部 100 关，并保留原有全部游戏验收。每章首、中、末关捕获开局、首步预览与清空截图；第 1、50、100 关检查键盘修饰键、焦点、暂停、提示、撤销、刷新续玩和重来。
- Pages 构建和真实公网 smoke 还会在第 100 关真实消除、刷新恢复并通过剩余按钮操作清空，核对 exact-SHA 标记与已完成存档。
- 实际是否通过以相应提交的完整 GitHub Actions 和截图复核为准。源代码审查、证书通过或单个作业通过都不代表已上线。
- 桌面 1536×1024 与手机尺寸 390×844 的 Chromium 不等于真实 iOS/Android、Safari、Firefox、屏幕阅读器或完整 WCAG 认证。
