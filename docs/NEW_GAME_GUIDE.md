# 新模块接入与验收

## 最小目录与边界

- `src/games/nameLogic.ts`：规则、状态转移、获胜判断、关卡和可验证解法。不依赖 React、DOM 或存储。
- `src/games/Name.tsx`：默认导出 `GameProps` 组件。CSS 必须使用模块自己的根类名，避免改坏其他棋盘。
- `tests/name.test.tsx`：合法/非法动作、解法证书、状态中断和真实 DOM 操作。
- `e2e/name.spec.ts`：通过真实可访问控件完成每个关卡。不得直接修改组件状态或 localStorage 伪造通关。

相关游戏可以共享经过测试的搜索器或组件，但不同颜色、尺寸、难度不构成新游戏。不要为路线图中的未完成候选注册入口。

## 外壳协议

`level` 为从 0 开始的关卡索引。`resetToken`、`hintToken`、`undoToken` 是单调变化的事件标记，不能假定只等于 1。`paused` 时禁用所有会改变局面的输入，并冻结 AI/动画/计时任务；恢复时不能重复执行旧回合。组件卸载时清理 timer、键盘事件、动画帧和 GPU 资源。

`onStatus(text)` 提供可读的教学或纠错反馈。`onComplete()` 只能由真实获胜条件触发，每轮只报告一次。不要把解法播放结束直接当作胜利。切换关卡与重来可能重挂载组件，状态不能泄漏到下一局。

撤销应与玩家的决策对应：对弈游戏通常撤销玩家动作和随后 AI 回应；执行中请求撤销也要清理延迟动作。提示来自当前局面，不可盲目套用开局证书。搜索到达预算时明确说明未找到可靠建议；不得把超时解释成死局或无解。

## 关卡与算法

1. 每关提供稳定 ID、教学目标、初始状态与一份合法解法证书。
2. 测试通过实际转移函数逐步重放证书，再独立验证获胜条件。
3. 需要唯一解的谜题独立计数至第二个解；允许多解的谜题接受所有合法终局。
4. 提示搜索必须有确定性节点预算，手机上不能无界阻塞主线程。
5. 校验非法索引、越界、重复动作和终局后的输入。不要依赖 UI 按钮禁用来保证规则安全。
6. 扩展已有游戏时保持旧关卡索引不变，只在末尾追加；否则已有本地成绩会指向错误题目。

## 注册与展示

在 `src/lib/catalog.ts` 添加稳定且不复用的 ID；在 `src/lib/registry.ts` 添加轻量元数据、真实关卡数、来源说明和 `lazy` 导入。不要从注册表导入关卡搜索器。把新关卡包加入 `tests/catalogContract.test.ts`，同步真实总数、README 和路线图。

卡片插图只用于导航。核心规则图使用可操作 DOM/SVG 或程序化 Three.js；3D 不可用时仍能读懂规则和完成游戏。为图片记录来源，避免商标角色与来源不明素材。

## 发布门槛

- 类型检查、全量单元/DOM 测试、生产构建通过。
- 所有关卡通过桌面与移动尺寸 Chromium 的真实操作；测试不得隐藏页面错误。
- 检查开局、中段、最后一关截图，特别检查小屏棋子比例、线索、按钮遮挡与横向溢出。
- 用键盘和点击完成核心操作；提供非颜色状态提示、焦点样式及减少动态效果支持。
- 检查重来、暂停/恢复、提示、撤销、重复点击和换关。
- 宽松开源代码也要检查素材、字体、音频、联网行为与依赖许可证。保留固定版本与完整上游声明。
- 只有确切提交通过 CI 和截图复核后才合入主分支；不把手机窗口模拟描述为真机或完整无障碍认证。
