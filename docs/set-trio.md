# 三卡共鸣

An original visible-attribute card puzzle for Playgarden. This is not a port,
licensed SET product, or use of official SET artwork. The general mathematical
rule is implemented independently in TypeScript. Code, 18 authored lessons,
interface, and programmatic SVG artwork are GPL-3.0-only under Playgarden's root
LICENSE and distributed `playgarden-COPYING.txt`. No additional dependency or
third-party source is included.

## Rules and interaction

Cards have four ternary attributes: color (red/indigo/teal), shape
(circle/triangle/diamond), symbol count (1/2/3), and fill
(solid/outline/hatching). Three cards form a valid group exactly when every
attribute is either identical on all three or different on all three. All legal
groups are accepted, including alternatives to the authored partition. Clear
every card to complete a lesson.

Select up to three cards, inspect four independent attribute indicators, then
confirm. Invalid previews are non-destructive. Valid groups can strand the
remaining cards; undo restores the most recent removal and previews it again.
There is no time limit or penalty. Tab, Enter/Space, arrow keys, Home and End are
supported. Color, shape, count and fill also have explicit text labels. Controls
have at least 44px targets. Pause disables game interactions.

## Campaign design

Every board is written explicitly as disjoint valid triples, which provide a
constructive clear-the-board arrangement. These triples are interleaved for
display and never used to judge the player's answer or to compute a hint.
Lessons are not generated by shuffling, rotating or renaming another board.

1. Six cards: count lines with two shapes, exposing the two-same/one-different error.
2. Nine cards: full shape/count grid with multiple grouping directions.
3. Six cards: a count line crossed with a separate color line.
4. Nine cards: combined color/shape changes, a count line, and a color line.
5. Six cards: outline joins solid; fixed color and shape also differ between lines.
6. Nine cards: count lines and a three-fill ladder coexist.
7. Nine cards: color, shape and count each vary in a different texture context.
8. Six cards: an all-four-changing triple contrasts with a two-attribute-changing triple.
9. Nine cards: each texture uses a different pair of changing attributes.
10. Twelve cards: two count lines and two color lines share a larger table.
11. Nine cards: a correlated color/shape/fill plane allows alternative partitions.
12. Twelve cards: three color/fill lines plus a shape/count branch.
13. Nine cards: offset fill cycles change otherwise similar three-attribute groups.
14. Twelve cards: texture-preserving lines and a cross-texture line coexist.
15. Twelve cards: four independently changing attribute axes.
16. Twelve cards: parallel all-four-changing lines with distinct offsets.
17. Twelve cards: opposing attribute cycles plus a color/fill line.
18. Twelve cards: mixed directions combine three- and four-attribute variation.

## Hints and persistence

Hints solve the exact current visible-card partition problem, at most 12 cards
and 4096 subsets. They show one safe next group without mutating selection or
removals. If the current board is stranded, they inspect removal prefixes and
report the minimum number of undos needed to return to a solvable board. They
make no claim of a unique solution or uniquely optimal play.

Resume key: `playgarden.set-trio.v1`.
Per-level saves: `playgarden.set-trio.v1.round.<zero-based-level>`.
Saves contain a schema version, lesson id, exact board fingerprint, legal
removal actions, and current selection. Loading replays removals, rejecting
invalid groups, repeats, missing cards, excessive data and invalid drafts.
Completion is derived from the replayed board. Storage failures are disclosed;
explicit restarts honor the shell's `freshStart` even if storage removal fails.

## Targeted browser coverage

`e2e/set-trio.spec.ts` covers first, middle and final completion using an
independent rule expression read from the displayed cards, a non-authored legal
partition, invalid preview/confirmation, hints without mutation, keyboard or
touch activation, target dimensions, pause, undo, restart, legal save restore,
corrupt save rejection, screenshots and page errors. It uses the repository's
desktop and 390px touch projects. Run only through the final targeted E2E
workflow. No unit suite or campaign proof sweep is part of this addition.
