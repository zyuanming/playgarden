# 可玩性质量门槛

通过解法回放只说明程序能完成题目，不等于游戏已经好玩。每批加入主分支前，还要由未编写该模块的人检查：

1. 规则和关键决策是否确实不同，不能靠换皮凑数量。
2. 第一次进入是否知道目标、第一步和如何纠错。
3. 抽查首关、中段和末关，确认难度来自有意义的选择，而不是更多重复点击。
4. 检查提示是否解释真实依据；搜索得到的步骤要如实标明，不冒充简单逻辑推导。
5. 检查触屏目标、文字对比、选中状态、撤销、重来、暂停和换关后的视口/焦点。
6. 将源码发现与实际浏览器观察分开记录。移动尺寸 Chromium 不等于真机或屏幕阅读器认证。

## 已发现并修复的实例

- 完成按钮原来位于长说明底部：改为棋盘前的通关操作区，下一关复位视口与标题焦点，并增加点击、滚动和键盘回归。
- 帐篷工具栏的当前格不够明显：增加持续描边和明确的行列说明。
- 点线游戏的细窄命中区：扩大到至少 44×44，并增强空边对比。
- 坐标小字：增大并提高对比，保持禁用格不褪色。
- 物理实验调整参数后丢失上次结果：保留上一次试验条件与观察，便于比较。
- 最小连接网的按钮排序泄露答案：打乱展示顺序、重映射证书，检查每关不能直接选择前 n−1 条线路通关。
- 解结提示在第一步后消失：保留两步提示，同时提供图结构和冲突的文字说明。

- 算式谜题直接揭示整盘答案：优先展示来自交叉数字段、行列与运算笼的可解释候选推导，穷举仅作明确标注的后备。
- 条件分拣末关任务单抄出了完整程序：后半段改为从完整目标表归纳优先级，通关后仍可检查任意包裹的执行过程。
- 巡回行走后刚用过的道路不可再用：将键盘焦点转移到可走道路，并覆盖连续多步键盘操作。

这些例子不代表所有游戏已经完成可访问性认证。每次发布仍需对应提交的完整自动检查、浏览器操作与截图复核。
