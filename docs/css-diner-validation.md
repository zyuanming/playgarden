# Validation contract

This package is an isolated candidate, not a published game. Parent integration owns the catalog, registry, shared host, licenses/runtime manifests, workflow, Git and remote publication.

The authored game stays at 32 puzzles. Selector matching differs from Flexbox Froggy's layout-property matching: the original `fireRule` uses the input as a selector only inside `.table`; the original `checkResults` checks the exact target DOM set by clone/markup comparison. It neither compares answer text nor grants success for counts alone. `js/levels.js` and `css/style.css` are exact cleared bytes. The final screen is earned by solving puzzle 32, while campaign completion requires all 32 independently solved entries.

Allowed local validation: read-only source/license/hash checks, archive integrity, JS/TS syntax parsing. No game/browser runtime, local server, dependency install, unit test or campaign solver sweep is included in that claim. The host and E2E still require the parent's reviewed typechecked build and the single targeted CI invocation `npm run test:e2e -- e2e/css-diner.spec.ts` using the existing desktop/mobile projects. Actual screenshots must be opened and reviewed after CI. No screenshot or gameplay-pass claim is made before that.

The E2E contains no progress/clock/engine/win writes and no seeded completion. It enters real selectors and clicks native controls. It checks first/middle/final boards; zero-match/malformed/same-count wrong selectors; the alternative first-board solution `plate:nth-child(n)`; correct completion; paused wrong-feedback and next-level timers; resumption; native numeric and menu navigation; draft persistence; retry; original ending; 3/32 rather than false full completion; restored ending; real 320px editor controls; rapid exit/reentry while a timer is pending; confirmed native full reset; no unrelated keys touched, network calls or page errors. Screenshot capture is part of the future E2E, not a local artifact.

The iframe uses `sandbox="allow-scripts"`, no same-origin privilege, and a CSP forbidding external/resource/network execution. Parent messages validate source window, opaque child origin, random session, revision and count; child messages validate parent window, real referrer origin and session. Init is idempotent, duplicate/late readiness cannot replay the campaign, and React effect replay reclaims rather than disposes a live frame. Every native game timer is owned by the bridge; pause preserves remaining delay, navigation/reset/disposal cancel stale work. Parent event listeners and timeout guards stop on unmount. Completion needs both the matching validated level report and its saved actual solved mark. Valid completion/navigation crossing a host pause are retained in a bounded same-session/current-level mailbox; resume flushes completion before navigation, and real unmount discards pending work. Navigation also validates its source level.

The historical earned ending and the final puzzle’s last displayed ending/retry state are distinct validated flags. Restoring a final ending initializes the native level UI before rendering the ending; an active final retry restores its real draft instead.

Storage belongs only to `playgarden.css-diner.v1.state`, catches malformed/denied storage and bounds all 32 guesses/drafts. Solved counts are derived; stored arbitrary counters are ignored. Native reset creates a fresh progress object and never touches generic `progress`, generic `currentLevel` or the shared campaign key. The original full-reset confirmation clearly states that already-earned shared-lobby history stays intact. Restart/retry preserves historical earned completion.

At 390px/320px the editor and sidebar stack; the table retains original food sizes and scrolls horizontally. No authored board is scaled into illegibility or clipped without a scroll path. Keyboard-focusable HTML and tap food inspection expose the original labels. Target outlines remain visible with reduced motion. This layout awaits actual CI screenshots for final visual verification.
