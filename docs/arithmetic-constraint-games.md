# 和数与算笼模块

这两款游戏采用原创 MIT 代码、关卡与图形，不导入第三方题库或游戏素材。

## 和数庭院

横向、纵向每段白格填写 1–9；同一段不重复，数字和必须等于箭头线索。黑格切断连续段。12 关从短段交叉递进到有分隔的长短混合段，玩家需要交叉筛选数字组合。

## 算笼工坊

每行每列使用 1–N 各一次；粗边框笼中的数字必须满足标注的运算结果。减法按大数减小数，除法按大数除小数且必须整除。同笼数字仍遵守行列限制，并不额外假定整个笼无重复。12 关从 3×3 递进到 5×5。

## 架构与检查

- 两款游戏共享数字输入、选择、键盘与不可变历史管理，但线索语义和约束构建独立。
- 关卡只包含公开线索；答案证书位于测试 fixtures，不由玩法模块导入。
- 提示先以有预算的约束搜索验证当前填写可行，再从公开横竖段、运算笼和行列规则筛选与已填数字相容的组合；优先展示线索最少、候选最少的单格交集推理，无法直接推理时才解释完整枚举证明。局部候选不借用答案或隐藏的传播结果，并与可行性搜索共享组合检查预算。
- 矛盾修复仍需证明当前填写无解，再以公开线索的唯一解证明某一填写确实错误；预算耗尽不会被当成证明。
- 单关重来与换关重建状态；暂停不消耗提示/撤销输入，终局只回报一次。
- 测试验证唯一性、独立解法枚举、全部 24 关提示引导解题及实际组件操作、局部教学解释、键盘、暂停、撤销与重置。最终集成状态以对应提交的完整检查为准。

主要选择器为 `data-arithmetic-puzzle`、`data-arithmetic-cell` 与 `data-value`；数字键盘按钮的可访问名称是“填入 N”。
