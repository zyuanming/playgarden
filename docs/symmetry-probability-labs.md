# Symmetry Repair and Probability Bag

Original code and authored curricula, SPDX-License-Identifier: MIT. No external images, audio, runtime dependencies, random judging, or hidden solution certificates.

## Components and integration

- `SymmetryRepair.tsx`, 12 zero-based levels from `symmetryRepairLevels.ts`.
- `ProbabilityBag.tsx`, 12 zero-based levels from `probabilityBagLevels.ts`.
- Both accept the repository `GameProps`. A keyed inner round resets when `level` or `resetToken` changes; hint and undo tokens are consumed while paused or completed. `onComplete` fires once per completed round. Completion freezes editing/undo; the shell can reset or move on.
- Shared styles and cancellation/focus helpers are `symmetryProbability.css` and `symmetryProbabilityRound.ts`.

## Public rules and progression

Symmetry Repair edits a binary square pattern under public transformation generators, immutable anchors, an exact filled-cell total, and a finite net repair budget. Unknown `?` cells must be decided. A cell costs one budget unit if its current state differs from the initial state; restoring the initial state refunds that unit. Thus resolving an initial `?` costs one unit whichever value is chosen. There is no hidden image and all satisfying patterns pass. This is not a tile-cover or row-run reconstruction game.

Progression: left/right mirror → up/down mirror → half-turn → main diagonal → anti-diagonal → quarter-turn → two mirrors → mirror plus half-turn → odd-grid rotation center → two diagonals → complete square symmetry → tight-budget repair. Focus outlines the full orbit generated by ALL listed constraints. `!` marks a conflicting orbit, `锁` is an immutable anchor, and glyphs distinguish filled/empty/unknown without color.

Probability Bag chooses three nonnegative integer token counts with a fixed final bag size. The UI accepts temporary partial bags and labels their actual denominator. Level goals may add minimum/maximum counts and a material-point cap. All probabilities use reduced integer fractions, with zero denominator yielding undefined and never passing any target. Conditional denominators contain only the given population. Without-replacement pairs use distinguishable physical tokens and denominator N(N−1); replacement pairs use N². Ordered pairs count one order; “one each” counts both orders. There are no monetary stakes, empirical success conditions, or luck-based scores.

Progression: one-draw fraction → union → conditioning → same-type no-replacement → unordered mixed pairs → ordered mixed pairs → independent replacement → at-least-once and conditioning → cost-limited composition → mixed protocols → quadratic pair constraints → combined final design.

## Hint semantics and cancellation

Symmetry enumerates all public orbit assignments up to 32,768 candidates, minimizing number of cell differences from the ACTUAL current board. It may suggest changing an earlier choice and says so explicitly. It prioritizes restoring a spent cell when necessary to respect the budget. No claims of minimality or impossibility are made after a capped search. Probability enumerates at most 256 full integer compositions, minimizes L1 add/remove distance, and removes extras before adding to a full bag. Neither hint applies its move.

Both run cooperative, queued batches. A fresh hint, editing, undo, pause, reset, completion, cancellation, or unmount aborts old work. Stale results are discarded. Reset and pause repair focus only if it is inside the game; external shell focus is preserved and all focus repairs use `preventScroll`.

## Public automation selectors

Symmetry:

- `[data-symmetry-host]`, `[data-symmetry-game]`
- game attributes: `data-symmetry-board` row-major string using `0`, `1`, `?`; `data-symmetry-won="true|false"`
- `[data-symmetry-cell="0"]` through `size²−1`; `data-value`, `data-locked`, `data-orbit`, `data-conflict`, `data-hint`
- `[data-symmetry-status]`, `[data-symmetry-orbit]`
- Paint buttons have exact accessible names `■ 填充`, `□ 留空`, `? 恢复未定`.
- Unmodified `F`, `E`, `?` on a cell directly assign filled, empty, unresolved (only if initially unresolved). Arrows navigate with wrapping and preventScroll. Ctrl, Meta, Alt combinations pass unchanged. Locked cells remain focusable for orbit exploration.

Probability:

- `[data-probability-host]`, `[data-probability-game]`
- game attributes: `data-probability-counts="A,B,C"`, `data-probability-won="true|false"`
- `[data-probability-add="0|1|2"]`, `[data-probability-remove="0|1|2"]`
- `[data-probability-count="0|1|2"]`, `[data-probability-token="0|1|2"]`
- `[data-probability-target="index"]` with `data-matched`; `[data-probability-value="index"]`; `[data-probability-status]`
- Every control is native and at least 44 px; Tab, Enter, Space work normally with no global keyboard interception.

## Test certificate format (test-only)

Certificates are final states, not private answer keys. Never import them into game code. Generate them by solving only the exported public clues with an independent oracle, then verify them independently before driving the UI.

```ts
type SymmetryCertificate = {
  game: "symmetry-repair";
  levelId: string; // sr-01 … sr-12
  board: (0 | 1)[]; // row-major, length size²
};
type ProbabilityCertificate = {
  game: "probability-bag";
  levelId: string; // pb-01 … pb-12
  counts: [number, number, number];
};
```

`tests/symmetryProbabilityOracle.ts` implements a coordinate/equality-matrix oracle for symmetry and enumerates distinguishable physical token pairs for probability. It does not use production transformations, orbit traversal, probabilities, or win predicates. `independentSymmetrySolutions` and `independentBagSolutions` produce certificates for browser tests. These helpers are test-only and have no runtime importers.

UI replay: Symmetry resets, then presses `f` or `e` on every differing unlocked cell. Stop if any valid pattern completes early. Probability first removes excess counts across all types, then adds missing counts. All 24 journeys are covered in `symmetryProbabilityGames.test.tsx`, including StrictMode completion idempotence. Pure tests exhaustively cross-check 3×3 binary patterns, every full bag composition for every authored level, and event formulas against physical-token enumeration.
